# Circuit Bastion

> 一款把塔防、自走棋与可视化编程合并到同一套规则中的轻量策略游戏。

## 1. 项目概述

### 1.1 一句话描述

玩家通过布置防御节点、连接信号线路并编写少量规则，构建一座会自动运行的“电路堡垒”。每一轮战斗结束后，玩家重组模块、调整程序，再观察自己的系统如何处理下一批敌人。

### 1.2 设计目标

- 用塔防提供清晰的空间决策和守线压力。
- 用自走棋提供有限资源下的阵容构筑、随机选择和组合成长。
- 用编程提供可解释、可调试、可复用的行为控制。
- 保持规则数量有限，让玩家能在短时间内读懂自己的系统。
- 让失败主要来自系统设计，而不是操作速度或隐藏数值。

### 1.3 核心体验

玩家不直接操控单个炮塔，而是设计一套能自动运行的防御系统。每个模块都能被看懂、被替换、被组合。战斗中的异常也应该能追溯到具体的线路、条件或模块。

## 2. 设计支柱

### 可读

战场上的每一次攻击、转发、阻塞和失效都通过颜色、连线和简短日志表达。玩家可以暂停战斗，沿着信号路径找到问题。

### 可组合

单个模块功能简单，价值来自位置、接口和组合方式。模块之间不依赖大量专属配方，避免记忆负担。

### 可编程

玩家编写的是小型规则片段，不需要学习完整编程语言。规则由触发器、条件和动作组成，拖拽或文本模式都可以编辑。

### 有限

每一局只提供有限的空间、能源、端口和改写次数。限制让玩家需要取舍，也让一个看似普通的模块产生长期价值。

## 3. 核心循环

```text
侦测敌情 → 购买或发现模块 → 放置并连线 → 编写规则 →
运行一波 → 读取结果与故障日志 → 领取奖励 → 改造系统
```

一局由若干个短回合组成。玩家在准备阶段进行大部分决策，战斗阶段系统自动运行。战斗可以暂停和加速，但不能直接点击敌人造成伤害。

### 3.1 准备阶段

1. 查看下一波敌人的类型、路线和一个主要特性。
2. 从有限的模块商店或事件奖励中选择内容。
3. 在网格上放置模块，调整输入输出方向。
4. 连接信号线和能源线。
5. 编辑规则，执行静态检查。
6. 锁定方案并开始战斗。

### 3.2 战斗阶段

- 敌人按路线或事件生成。
- 信号在节点之间传播，存在传播延迟和带宽上限。
- 模块依据输入、内部状态和规则执行动作。
- 玩家可以暂停、加速或查看任意一次事件的来源。
- 核心目标被摧毁或成功撑过波次后，战斗结束。

### 3.3 复盘阶段

战斗结束后显示三类信息：

- **结果**：漏怪数量、核心剩余耐久、能源峰值、系统过载次数。
- **原因**：哪些规则触发，哪些模块没有收到信号，哪里产生了拥塞。
- **机会**：下一波最值得修改的一个瓶颈。

复盘只给出事实和可追踪路径，不直接替玩家给出最优解。

## 4. 战场与线路

### 4.1 网格

战场由小型方格组成。不同于传统塔防只把网格当作建筑位置，Circuit Bastion 中网格同时决定：

- 敌人的移动路径。
- 防御模块的覆盖范围。
- 信号线的长度和传播延迟。
- 模块之间能否形成闭环。
- 线路是否会经过干扰区域。

### 4.2 三种连接

| 连接 | 作用 | 主要限制 |
| --- | --- | --- |
| 能源线 | 为模块提供持续功率 | 总功率和峰值功率 |
| 信号线 | 传递事件、目标和状态 | 带宽、延迟和端口方向 |
| 冷却线 | 将过热转移到散热节点 | 长度和散热容量 |

三种线都使用相同的网格空间，因此玩家必须在“连得上”和“放得下”之间取舍。

### 4.3 节点

- **核心节点**：需要保护的目标，拥有有限耐久。
- **入口节点**：敌人从这里进入。
- **输出节点**：部分攻击模块必须连接到输出节点才能影响敌人。
- **中继节点**：延长信号范围或复制信号。
- **干扰节点**：改变传播速度、方向或信号内容。

## 5. 模块系统

模块分为功能类别，但类别不是固定职业。一个模块的实际定位取决于它接收到的信号和规则。

### 5.1 观测模块

读取战场状态并生成事件。

- **扫描器**：发现范围内的敌人，输出敌人标签和距离。
- **计数器**：记录指定标签的数量、连续出现次数或通过次数。
- **探针**：读取线路拥塞、能源和模块过热状态。

### 5.2 处理模块

改变信号内容或顺序。

- **过滤器**：只放行满足条件的事件。
- **排序器**：按距离、生命值、标签或到达时间排列目标。
- **分流器**：把不同标签送往不同线路。
- **延迟器**：故意延迟信号，制造同步窗口。

### 5.3 执行模块

把信号转换成防御行为。

- **脉冲炮**：单体高伤害，适合处理高威胁目标。
- **弧光塔**：在多个目标之间跳跃，适合处理密集敌群。
- **减速场**：改变区域内敌人的移动速度。
- **屏障发生器**：短时间保护核心或线路节点。
- **维修臂**：修复模块或线路，但会占用大量能源。

### 5.4 基础设施模块

- **电池**：储存能源，缓解峰值消耗。
- **散热器**：降低附近模块过热。
- **缓存**：储存短时间内未被处理的事件。
- **路由器**：扩大端口数量，但本身会增加延迟。
- **复制器**：复制一次信号，需要较高带宽。

### 5.5 模块质量与升级

模块不使用传统的五级稀有度作为主要成长方式。每个模块拥有三个可替换的固件槽：

- **接口固件**：增加端口或改变连接方向。
- **逻辑固件**：改变触发条件或可用动作。
- **物理固件**：改变伤害、范围、容量或散热。

升级会扩大模块的可能性，也会增加功耗、延迟或规则复杂度。高等级模块不应自动优于低等级模块。

## 6. 轻量规则语言

### 6.1 规则结构

每条规则由三部分组成：

```text
当 <触发器> 且 <条件> 时，执行 <动作>
```

示例：

```text
当 扫描器发现敌人 且 敌人标签包含“装甲” 时，
将目标发送到 脉冲炮
```

### 6.2 触发器

- 发现目标
- 目标进入或离开范围
- 模块收到信号
- 能源低于阈值
- 温度超过阈值
- 波次开始或结束
- 某个计数器达到阈值

### 6.3 条件

- 标签、距离、生命值和速度
- 信号来源和到达时间
- 当前能源、温度、带宽和冷却
- 敌人数量或特定事件的连续次数

### 6.4 动作

- 发送、复制、过滤或延迟信号
- 选择目标并攻击
- 改变模块模式
- 打开或关闭线路
- 消耗能源换取护盾、维修或过载输出

### 6.5 规则限制

- 每个模块有有限规则槽。
- 规则按优先级从上到下检查。
- 同一帧内的循环触发次数有限。
- 规则需要通过端口类型检查和循环检查。
- 玩家可以把规则保存为“宏”，但宏会占用额外容量。

系统允许玩家写出低效方案，但必须让低效的原因可见。错误信息需要指出具体模块、线路和事件，而不是只显示“程序错误”。

## 7. 自走棋式构筑

### 7.1 商店

每个准备阶段出现有限数量的模块、固件和线路配件。刷新需要消耗资源，锁定可以保留当前商店。商店池会根据本局已经购买的类别动态变化，但不会强迫玩家追逐唯一流派。

### 7.2 合并

三个相同模块可以合并为一个“重构模块”。重构不是简单增加数值，而是从三个模块中选择一项保留特性，并获得一个新的接口。

例如，三个弧光塔可以重构为以下方向之一：

- 每次跳跃伤害降低，但允许跳跃到隐藏目标。
- 只能攻击装甲目标，但首次命中会标记目标。
- 伤害不变，但需要额外冷却线。

### 7.3 阵容概念

阵容由系统行为定义，而不是固定羁绊。常见构筑方向包括：

- **高带宽网络**：复制与分流大量事件，依靠多座低功率执行模块。
- **脉冲网络**：积攒能源后进行短时间爆发。
- **热交换网络**：主动让部分模块过热，再通过转移热量获得额外效果。
- **延迟网络**：利用缓存和延迟器，让多个攻击在同一时刻触发。
- **最小系统**：模块数量少，依靠精确规则和高质量接口。

## 8. 敌人与关卡

### 8.1 敌人属性

敌人拥有少量通用属性和一个可读标签：

- 生命值、速度和护甲
- 对某类伤害的抗性
- 是否能干扰线路
- 是否会分裂、伪装、维修或改变路线
- 一个主要标签，例如“群体”“装甲”“隐匿”“载荷”“干扰”

### 8.2 关卡结构

每张地图由若干段组成，每段包含普通波、选择波和首领波。玩家可以在选择波前选择风险：

- 增加敌人数量，换取更高资源。
- 增加线路干扰，换取稀有固件。
- 缩小可用空间，换取一次免费重构。

### 8.3 首领

首领不是单纯拥有更多生命值。首领会改变系统约束，例如：

- 暂时关闭某种连接。
- 复制玩家最近使用的一条规则并反向执行。
- 在战场上生成新的入口。
- 让某一类信号产生延迟。

首领战的重点是检测系统是否有冗余和备用路径。

## 9. 资源与失败

资源分为三种：

- **电荷**：购买模块、刷新商店和启动高功率行为。
- **结构点**：扩展网格、增加端口和修复严重损坏。
- **样本**：从敌人和事件中获得，用于解锁固件分支。

失败后保留少量长期解锁内容，但不保留本局的模块和资源。长期解锁只提供新的表达方式，不直接提供不可替代的数值优势。

玩家可以随时在沙盒模式中测试已解锁模块。沙盒模式没有奖励，允许逐帧查看信号和导出日志。

## 10. 游戏模式

### 10.1 远征模式

单局约 20 至 30 分钟。地图、商店和敌人组合带有随机性，适合重复游玩。

### 10.2 设计模式

使用固定资源和固定敌人，玩家尝试完成指定目标，例如“只使用两个执行模块”或“不能产生线路拥塞”。

### 10.3 竞速模式

以相同种子生成地图，比较通关时间、核心剩余耐久和系统复杂度。排行榜记录规则数量、模块数量和总能源消耗，避免单一维度决定成绩。

### 10.4 分享模式

玩家可以导出一局的模块图、规则文本和回放。导入后可以在本地运行，不需要连接服务器执行玩家逻辑。

## 11. 界面草案

### 主战场

- 中央区域显示网格、敌人、模块和三种线路。
- 左侧显示下一波预览、敌人标签和路线变化。
- 右侧显示当前选中模块的端口、规则槽和资源消耗。
- 底部显示能源、带宽、温度和时间控制。

### 调试视图

- 点击一次事件可以高亮完整传播路径。
- 点击模块可以查看最近十次输入、输出和未执行原因。
- 拥塞、过热和规则冲突分别使用不同视觉编码。
- 支持只显示某一类信号，避免线路过多时无法阅读。

### 可访问性

- 线路颜色同时使用纹理或图标区分。
- 所有动画都有暂停和减速选项。
- 规则编辑器支持纯键盘操作。
- 重要状态提供文本日志和屏幕阅读器标签。

## 12. 技术方向

### 模拟层

使用确定性事件模拟器。每个事件包含时间戳、来源、目标、类型和载荷。暂停、加速、回放和复盘都基于同一份事件记录。

### 规则执行

规则先转换为有限状态的中间表示，再进行静态检查和运行时执行。运行时限制单帧事件数量、递归深度和循环触发次数。

### 数据驱动

模块、敌人、固件和关卡尽量使用数据文件描述。规则动作通过白名单注册，避免让内容配置直接执行任意代码。

### 存档与回放

存档包含随机种子、玩家决策和版本号。回放只记录输入和种子，不保存每一帧完整状态。版本变更后需要提供迁移策略，无法迁移的回放应明确标记版本。

## 13. 最小可行版本

第一阶段只实现一张地图和以下内容：

- 10 个模块，包括扫描、过滤、分流、脉冲炮、弧光塔、减速场、电池、散热器、缓存和路由器。
- 6 种敌人和 1 个首领。
- 3 种连接，能源、信号和冷却。
- 触发器、条件和动作组成的规则编辑器。
- 10 波远征流程。
- 暂停、加速、单事件追踪和战斗日志。
- 商店、模块合并和 3 个固件分支。
- 本地存档与回放导出。

第一阶段不加入联网对战、复杂剧情、角色系统和大型科技树。先验证玩家能否理解“设计规则—运行系统—定位问题—重构系统”的循环。

## 14. 后续扩展

- 可改变地图拓扑的移动节点。
- 需要多个玩家协作的双核心关卡。
- 允许玩家发布规则挑战的社区关卡。
- 以有限指令集为基础的脚本模式。
- 更复杂的敌方网络，让敌人也拥有可观察的信号系统。
- 规则和模块的可视化差异分析，帮助玩家比较两个版本的系统。

## 15. 待决定事项

- 规则编辑器是否同时支持积木模式和文本模式。
- 线路是否允许穿过模块，还是必须绕行。
- 商店随机性和固定选择之间的比例。
- 模块受损后是暂时停机还是永久占用结构点。
- 是否允许玩家在战斗中修改规则，或者只允许暂停修改。
- 竞速模式如何衡量系统复杂度，避免鼓励无意义地减少模块数量。
- 分享的回放是否需要严格绑定游戏版本。

## 16. 术语表

| 术语 | 含义 |
| --- | --- |
| 模块 | 可以放置、供能、连线并执行规则的基本单元 |
| 端口 | 模块的输入或输出接口 |
| 事件 | 在线路中传播的目标、状态或环境变化 |
| 带宽 | 单位时间内线路可以处理的事件量 |
| 过热 | 模块高负载运行后的暂时性风险 |
| 固件 | 改变模块接口、逻辑或物理参数的升级项 |
| 重构 | 合并多个同类模块并选择新接口的成长操作 |
| 规则槽 | 模块可以保存的规则数量 |

## 17. 项目状态

当前仓库同时保存设计稿、Node.js 参考原型和 Godot 4 桌面垂直切片。Godot 版本优先验证战场阅读、确定性事件链与模块编排体验，内容数值仍会随着垂直切片测试调整。

## 18. 运行与发行

开发环境需要 Node.js 18 或更高版本：

```bash
npm ci
npm run check
npm start
```

推送 `v*` 标签后，GitHub Actions 会构建 Windows x64、Linux x64、macOS x64 和 macOS arm64 的 Node.js SEA 独立可执行文件，并同时上传一个不含 Node.js 的便携 Node 包作为 fallback。各平台下载包的运行方式记录在 [RUNNING.md](RUNNING.md) 中。

## 19. Godot 4 桌面垂直切片

桌面游戏版本使用 Godot 4，主场景位于 `scenes/main.tscn`，入口脚本为 `scripts/game_root.gd`。它提供深色科幻控制台、8×6 电路战场、三类线路、模块端口与规则卡片、波次节奏、事件追踪和暂停/倍速交互。确定性模拟位于 `scripts/simulation.gd`，视图位于 `godot/battle_view.gd`，两者通过快照与命令连接。

安装 Godot 4 后运行：

```bash
godot4 --path . --editor
# 或直接启动桌面垂直切片
godot4 --path .
```

无显示环境可进行脚本检查：

```bash
godot4 --headless --path . --scene res://scenes/main.tscn --quit-after 2 --display-driver headless --audio-driver Dummy --rendering-method gl_compatibility
# 确定性模拟冒烟测试
godot4 --headless --path . --script scripts/simulation_probe.gd
```

仓库中的 Node.js 页面仍保留用于设计稿对照和发行包 fallback，桌面垂直切片是后续玩法实现的主技术方向。
